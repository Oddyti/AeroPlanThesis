### 核心原则

- 标题取名：标题不是对内容的简单总结罗列，而是升华简洁贴切的高度概括。禁止犯“想要塞太多内容到标题”的错误，即想要在标题塞进两个以上的概括，而应该想想有没有更高层贴切的单表达。
- 行文风格：你不是在写代码项目的工程说明书，而是在写高水平科研论文。论文应该是工程的高度升华包装。

### 行文风格
**核心原则：摆事实 → 自然导出需求，而非先下结论再找论据。**

- 因果链推进：不分"结论段"和"论据段"。说事实的同时就是在论证问题，不要在段首喊完口号再列数据。好的行文读起来像推导，不像辩护。
- 动词口语化：用"需要"、"难以"、"容易"、"受...影响"，不用"构成了"、"提出了"、"具有"。动作的主语尽量是人或物理实体，不是抽象名词。
- 连接词承载逻辑："然而"表转折、"此外"表叠加、"因此"表因果。不用"这意味着"、"值得注意的是"、"如第X章所述"等零信息连接。
- 场景直入：直接描述技术问题，不用"在本文所关注的XXX场景中"、"对于XXX问题而言"等套壳。
- 句长自然：想清楚一句话讲什么就怎么讲。不刻意拆短句，也不刻意拉长句。读完能顺畅复述即可。
- 一段一个核心点：每段围绕一个意思展开。段与段之间要么递进、要么转折，避免信息平行罗列。

### 禁止AI味表达

**以下为 AI 味严重的表达举例：**

- "构成了尤为严峻的挑战" → 直接说挑战是什么
- "具有更强的动态性与时效性要求" → 具体说明快在哪、紧在哪
- "对XXX提出了极高要求" → 同义反复，删掉或换成具体约束
- "在本文所关注的XXX场景中" → 直接写"XXX 的跟踪/控制/规划"
- "这意味着" → 直接说结论，不用过渡
- "这两重目标在XXX下存在本质冲突" → 直接说怎么冲突、为什么冲突
- 对称句式（"一方面...另一方面..."、"不仅...更..."）→ 需要对比时才用，不滥用
